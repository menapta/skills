# SOLID skill

Use this skill when designing or reviewing object-oriented code.

## Principles
- SRP: one reason to change.
- OCP: extend without modifying stable code.
- LSP: subtypes must remain substitutable.
- ISP: prefer small, specific interfaces.
- DIP: depend on abstractions, not concretions.

## Guidance
- Split responsibilities that change for different reasons.
- Prefer composition over inheritance when appropriate.
- Keep interfaces focused.
- Invert dependencies at boundaries.
- Use abstractions only where they reduce coupling.

## Output style
- Explain which principle is being applied.
- Show the impact on maintainability and testability.
- Prefer practical examples over theory.
